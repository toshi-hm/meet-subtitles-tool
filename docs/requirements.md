# 要件定義

## 1. 目的

Google Meetの字幕を会議中に蓄積し、あとから読み返しやすい形でコピー・TXT保存・Google Drive保存できるChromium系ブラウザ拡張機能を提供する。

## 2. 対象ユーザーと利用シナリオ

- 会議内容をあとから確認したい参加者
- 手動で字幕をコピーし続ける負担を減らしたい参加者
- 会議終了後に字幕をGoogle Driveで管理したい参加者

基本シナリオは「拡張機能をインストールする → Meetに入室する → 字幕が自動でONになる → 会議中に字幕を蓄積する → 必要な時点でコピー／TXT保存する → 会議終了時にDriveへ自動保存する」である。

## 3. 対応環境

### 事実として確定した要件

- ChromeとEdgeを対象とする。
- 可能な範囲でChromiumベースのブラウザ全般を対象とする。
- TypeScript、Bun、WXT、Manifest V3を使用する。

### 実装方針

- コア機能は標準WebExtension APIとWXTの抽象化で実装する。
- Chrome／Edgeを第一検証対象とし、他のChromium系ブラウザでは字幕取得・ローカル保存を優先的に保証する。
- Google Drive OAuthは各ブラウザのIdentity APIと拡張機能ID・OAuth設定に依存するため、対応可否を手動検証する。

## 4. 機能要件

### FR-01 入室時の字幕自動ON

- Google Meetの会議画面を検出したら字幕ボタンの状態を確認する。
- 字幕がOFFの場合は自動でONにする。
- 字幕ボタンを検出できない場合は、字幕取得待ちの状態として再試行する。
- 自動ONに失敗した場合は、フローティングパネルに利用者が手動でONにする案内を表示する。

### FR-02 字幕の蓄積

- 会議中に表示された字幕を話者単位の発話レコードとして蓄積する。
- Meetが発話途中の文字列を更新する場合は、同一発話を更新し、更新途中の文字列を別レコードとして重複保存しない。
- 話者名を取得できない場合は `不明な話者` とする。
- Meetが自分の話者名を `あなた` と表示する場合は、Meet画面上で取得できる自分の表示名へ置換する。
- 表示名を取得できない場合は `自分` とし、メールアドレスを話者名として保存しない。
- 字幕の取得順を維持する。
- 字幕本文は拡張機能外の第三者サービスへ送信しない。

### FR-03 IndexedDBによる復元

- 字幕は取得ごとにIndexedDBへ保存する。
- Meetタブをリロードしても同一会議セッションの字幕を復元する。
- 一時的な通信切断やMeet側の再描画があっても、既に保存済みの字幕を失わない。
- 会議セッションの完了後は、保存済みデータをDrive同期・ローカルダウンロードに利用できる。

### FR-03a IndexedDBの保持期間

- Meetごとのセッション、字幕、同期キューは、IndexedDBへの書き込み開始時点から24時間保持する。
- 24時間経過後は、対象セッションに関連するIndexedDBレコードを自動削除する。
- 期限前のセッションや、別のMeetセッションのデータは削除しない。
- 自動削除はMeetページ起動時と、Meetページが開いている間の定期処理で実行する。

### FR-04 フローティングパネル

- Meetに入室済みの会議画面内だけに表示し、`meet.google.com/home`や入室前の待機画面には表示しない。
- パネルには字幕取得状態、保存件数、主要操作を表示する。
- パネル内に会議中に蓄積した字幕履歴を表示し、保存操作なしで古い字幕までスクロールして確認できる。
- IndexedDBから復元した同一セッションの字幕履歴を、入室後のパネルへ初期表示する。
- 履歴を上へスクロールしている間は、新しい字幕の取得で表示位置を末尾へ強制移動しない。
- 折りたたみ状態を提供する。
- パネル本体をドラッグして移動できる。
- パネルの端をドラッグして幅・高さを変更できる。
- ボタンの通常色は `#000048` とし、ホバー・押下時は別の色で表示する。
- Meetの画面操作を妨げにくい位置とサイズを初期値にする。
- キーボードフォーカス、ARIAラベル、十分なコントラストを確保する。

### FR-05 クリップボードコピー

- ボタン操作時点までの字幕を、指定フォーマットでクリップボードへコピーする。
- 成功・失敗をパネル内に通知する。
- 権限やブラウザ制限で失敗した場合はTXT保存を代替手段として案内する。

### FR-06 TXT保存

- ボタン操作時点までの字幕をUTF-8のTXTファイルとして保存する。
- ファイル名は `meet-subtitles-YYYY-MM-DD-HHmmss.txt` を基本とする。
- 同一会議で複数回保存しても、別ファイルとして保存できる。

### FR-07 Google Drive自動保存

- 保存先はマイドライブ直下の `Meet Subtitles` フォルダとする。
- 対象フォルダが拡張機能管理下に存在しない場合は作成する。
- 会議参加後のフローティングパネルから、字幕が0件でもGoogle Drive OAuthを開始・完了できる。
- 会議終了時点の字幕をTXTとしてフォルダ直下に保存する。
- 退出ボタン、会議終了表示、タブ終了、Meetページからのページ遷移を終了契機とする。
- タブ切り替えだけでは終了扱いにしない。
- 終了イベントで非同期処理が完了しない場合に備え、会議中も一定間隔でDriveへ同期する。
- 認証未完了・通信失敗・権限拒否の場合は、字幕をIndexedDBに残し、再試行可能な状態を表示する。
- 認証操作では字幕本文を送信せず、アクセストークン取得だけを行う。

## 5. 保存フォーマット

確定フォーマットは次の2行構成とする。発話ごとに空行を入れて可読性を確保する。

```text
[00:01:23] 話者名
発話内容

[00:01:31] 別の話者
次の発話内容
```

### 推論・実装上の補足

- Meetの字幕自体に安定した時刻がない場合があるため、`hh:mm:ss` は拡張機能が会議セッションで最初に字幕を取得した時点を `00:00:00` とする経過時間で実装する。
- ページリロード時もIndexedDBに保持したセッション開始時刻を使い、時刻をリセットしない。
- この時刻定義は、ユーザー指定の書式から補った実装上の仮定である。実際の時刻表示が必要になった場合は仕様変更する。

## 6. Google Drive認証・権限

Meetへのログインと、拡張機能によるDrive書き込み認可は別である。Meetにログイン済みでも、拡張機能がユーザーのDriveへファイルを作成する権限は自動付与されない。

- Chrome拡張機能のIdentity APIのWeb認証フローを利用し、初回のDrive保存操作に対してOAuth同意を要求する。
- 基本スコープは `https://www.googleapis.com/auth/drive.file` とする。
- OAuth Client ID、Google Cloudプロジェクト、Drive API有効化は利用者が拡張機能ポップアップから設定する。
- OAuth Client IDは拡張機能のポップアップに保存し、Client Secretは要求・保存しない。
- 同意画面は拡張機能の起動時ではなく、ユーザーがDrive保存を有効化・実行した時だけ表示する。
- `drive.file` は拡張機能が作成・利用するファイルに限定されるため、全Drive読み書き権限を要求しない。
- フォルダID、OAuth Client ID、アクセストークンは字幕本文やログと分離して拡張機能のローカルストレージで管理し、ログに出力しない。

## 7. 非機能要件

- NFR-01: 会議中の字幕取りこぼしを避けるため、DOM再描画・遅延ロード・タブリロードに耐える。
- NFR-02: UI表示がMeet本体の操作を妨げない。
- NFR-03: 字幕データは外部AI・分析サービスへ送信しない。
- NFR-04: Chrome／Edgeでビルド・静的検査・ユニットテストを通過する。
- NFR-05: lint/format checkとtestをGitHub Actionsの別workflowで実行する。
- NFR-06: 利用者向けREADMEだけでセットアップと利用方法が理解できる。

## 8. 制約・リスク

- MeetのDOMやaria-labelは将来変更される可能性がある。セレクタを集約し、検出不能時の案内を実装する。
- タブ終了時にネットワーク通信を確実に完了できる保証はない。IndexedDBと定期Drive同期を組み合わせる。
- Google OAuthの拡張機能ID、ストア配布、ブラウザごとのIdentity API差異がある。他のChromium系ブラウザは手動検証対象とする。
- 会議参加者の字幕は個人情報を含む可能性があるため、保存先と権限をREADMEで明示する。
